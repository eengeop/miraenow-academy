# Cloudflare 링크 저장소 1단계

현재 Vercel 배포는 가상 긴 이미지의 정적 포트폴리오 데모다. 이 단계는 별도 Cloudflare 배포를 위한 **D1 링크 기록 스키마와 코드**만 추가하며, 공개 API·버킷·실제 안내장 파일은 만들지 않는다.

`cloudflare/schema.sql`은 안내장의 R2 객체 키·형식·등록 및 삭제 예정 시각과 링크의 SHA-256 토큰 해시·활성 상태·만료 시각을 저장한다. 원본 토큰은 발급 결과로 한 번만 돌려주고 D1에는 기록하지 않는다. 재발급 시 같은 안내장의 이전 링크를 D1 일괄 실행으로 폐기한다. 링크 만료는 발급 후 30일과 안내장 등록 후 30일 중 빠른 시각이다. 조회 시 두 만료 시각과 폐기 상태를 모두 검사한다.

2단계 Worker는 `GET`·`HEAD /n/:token/asset` 및 `/n/:token/download`에서 D1 링크가 유효할 때만 비공개 R2 객체 키를 읽는다. 파일 형식과 다운로드 확장자를 유지하고, 응답을 저장·검색 색인하지 않도록 헤더를 설정한다. 공개 파일 목록이나 업로드·삭제 API는 제공하지 않는다.

3단계 Worker는 `GET`·`HEAD /n/:token`에서 링크와 R2 객체 존재를 확인한 뒤 이미지 또는 PDF 모바일 열람 화면을 제공한다. 화면의 파일 열람·다운로드 URL도 같은 토큰으로 보호한다. `npm run build:cloudflare`는 가상 화면 파일과 PDF.js를 `cloudflare/dist/`에 생성한다. 이 디렉터리는 Git에서 제외하며 실제 안내장 파일을 복사하지 않는다.

4단계 정리 작업은 예약 실행 시 만료된 안내장을 최대 100건 조회해 R2 관리 복사본을 삭제하고, 연결된 링크와 안내장 D1 기록을 삭제한다. R2 삭제가 실패하면 기록을 남겨 다음 실행에 재시도한다. 만료 시각부터 화면·파일 요청은 즉시 차단된다. 예약 실행 주기는 Cloudflare 배포 설정에서 정한다.

가상 PNG·PDF 등록, Cloudflare 배포와 모바일 사용자 확인을 마쳤다. 다음 단계는 실제 자료의 전달·원본·백업·접근·파기 기준 결정과 만료 후 원격 정리 결과 확인이다. 기준을 정하기 전에는 실제 학생 자료를 인터넷에 올리지 않는다. Vercel의 정적 데모는 그대로 유지한다.

`npm run check`의 D1 테스트는 Node의 메모리 SQLite에서 실제 SQL을 실행한다. Worker 테스트는 가상 D1·R2·정적 파일 바인딩으로 접근 차단과 화면·파일 형식을 확인한다. 실제 D1·R2 연결과 배포 주소의 가상 자료 검증 결과는 [Cloudflare 가상 안내장 데모](cloudflare-demo.md)에 기록한다.
