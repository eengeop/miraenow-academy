# Cloudflare 링크 저장소 1단계

현재 Vercel 배포는 가상 긴 이미지의 정적 포트폴리오 데모다. 이 단계는 별도 Cloudflare 배포를 위한 **D1 링크 기록 스키마와 코드**만 추가하며, 공개 API·버킷·실제 안내장 파일은 만들지 않는다.

`cloudflare/schema.sql`은 안내장의 R2 객체 키·형식·등록 및 삭제 예정 시각과 링크의 SHA-256 토큰 해시·활성 상태·만료 시각을 저장한다. 원본 토큰은 발급 결과로 한 번만 돌려주고 D1에는 기록하지 않는다. 재발급 시 같은 안내장의 이전 링크를 D1 일괄 실행으로 폐기한다. 링크 만료는 발급 후 30일과 안내장 등록 후 30일 중 빠른 시각이다. 조회 시 두 만료 시각과 폐기 상태를 모두 검사한다.

2단계 Worker는 `GET`·`HEAD /n/:token/asset` 및 `/n/:token/download`에서 D1 링크가 유효할 때만 비공개 R2 객체 키를 읽는다. 파일 형식과 다운로드 확장자를 유지하고, 응답을 저장·검색 색인하지 않도록 헤더를 설정한다. 공개 파일 목록이나 업로드·삭제 API는 제공하지 않는다. 이 코드는 아직 Cloudflare에 배포되지 않았고 화면 HTML도 제공하지 않는다.

다음 단계에서 안내장 화면, 만료 객체 삭제 작업, 가상 PNG·PDF 등록 명령, Cloudflare 설정·배포 및 모바일 검증을 진행한다. 실제 학생 자료는 운영 접근·백업·파기 기준을 정하기 전까지 올리지 않는다. Vercel의 정적 데모는 그대로 유지한다.

`npm run check`의 D1 테스트는 Node의 메모리 SQLite에서 실제 SQL을 실행한다. Worker 테스트는 가상 D1·R2 바인딩으로 접근 차단과 파일 형식을 확인한다. 실제 D1·R2 서비스 연결과 배포 환경 동작은 아직 검증하지 않았다.
