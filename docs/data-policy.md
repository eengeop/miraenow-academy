# 실제 안내장 데이터 운영 결정

이 문서는 실제 자료의 외부 제공 전 설계 결정을 기록한다. Cloudflare에는 가상 자료만 배포했다. 실제 안내장은 로컬에서만 검증하며 인터넷에 제공하지 않는다.

## 자료 범위

- 실제 안내장에는 학생 이름, 학년, 점수, 교사 의견이 포함될 수 있다.
- 포트폴리오, 공개 저장소, PR, 이슈, 화면 캡처에는 실제 학생 자료를 사용하지 않는다. 시연에는 가상 자료만 사용한다.
- 이 범위 밖의 정보가 필요해지면 자료 항목과 접근·보관 기준을 다시 검토한다.

## 확정한 운영 기준과 남은 확인

| 항목 | 확정한 기준 | 운영 전 확인 |
| --- | --- | --- |
| 열람 | 256비트 무작위 링크를 가진 사람은 열람·다운로드 가능. 발급 후 30일 만료, 폐기·재발급 지원. 오발송 시 즉시 폐기하고 수신자를 확인한 뒤 재발급 | 가상 자료로 원격 폐기·재발급을 검증함. 실제 자료 운영 전 안내장 ID와 수신자 대조 절차 마련 |
| 원본 | `uploads/` 원본은 안내장 등록일부터 30일에 운영자가 직접 삭제. 앱 관리 복사본은 등록일부터 30일 후 열람 차단·정리 | 수동 삭제일 기록과 실행 방법 준비. `uploads/`는 앱이 자동 삭제하지 않음 |
| 백업 | 운영자가 실제 안내장 파일의 별도 백업을 만들지 않음 | Cloudflare 기본 복구 이력과 제공자 내부 보존 범위 확인 |
| 배포 | Cloudflare Worker·D1·R2는 계정 소유자 한 명만 관리. 추가 멤버나 공유 API 토큰을 만들지 않음 | 현재 멤버·API 토큰·로그 설정과 실제 자료 접근·파기 방법 확인 |

## 오발송과 운영자 접근 절차

- 발송 전에 안내장과 수신자를 확인한다. 오발송을 알게 되면 해당 링크를 즉시 폐기하고 올바른 수신자를 다시 확인한 뒤 새 링크를 발급한다. 잘못 받은 사람이 이미 열람하거나 다운로드한 사본은 링크 폐기로 회수할 수 없으므로 그 사실과 후속 연락 여부를 운영자가 확인한다. 원격 운영 명령과 검증 방법은 [Cloudflare 가상 안내장 데모](cloudflare-demo.md)에 기록한다.
- Cloudflare Worker·D1·R2 관리는 계정 소유자 한 명으로 제한한다. 2026-11-14 대시보드에서 멤버 1명(Super admin)을 확인했다. 로그인된 기기와 2단계 인증 상태는 아직 확인하지 않았다. 추가 담당자가 필요해지면 필요한 자원에만 권한을 부여하도록 기준을 다시 정한다. [Cloudflare 멤버·역할 안내](https://developers.cloudflare.com/fundamentals/manage-members/)

## 수동 원본 삭제

로컬 등록 명령은 안내장 ID, `uploads/` 원본 경로, 등록일, 삭제 예정일(등록일 + 30일)을 Git 제외 경로 `private/originals.jsonl`에 기록한다. 운영자는 `npm run notices -- originals`로 예정일을 정기적으로 확인하고, 예정일에 원본을 직접 삭제한 뒤 `npm run notices -- confirm-deleted <안내장-ID>`로 완료를 기록한다. 파일이 남아 있으면 확인 명령은 실패한다. 앱의 만료 정리 작업은 `uploads/` 원본을 삭제하지 않는다. 이 기록은 로컬 등록에만 적용되며, Cloudflare 실제 자료 등록·알림 절차는 아직 없다.

## 실제 자료 배포 전 확인

- 계정 멤버 1명(Super admin)을 확인했다. 로그인된 기기·2단계 인증 상태는 추가 확인한다.
- 계정 API 토큰 1개는 다른 R2 버킷(`tellmedog`)의 객체 쓰기 권한으로 한정되어 있고, 사용자 API 토큰은 없다. Wrangler 로그인 방식과 전역 API 키 사용 여부는 추가 확인한다. 토큰 값은 문서나 PR에 적지 않는다.
- 데모 Worker의 Logs·Traces·Issues와 로그 내보내기 대상은 비활성/없음, 데모 R2 버킷의 Data Access Logs와 공개 도메인·개발 URL은 비활성임을 확인했다. D1 Queries 지표에는 실행한 SQL 문자열이 표시되어 안내장 ID와 토큰 해시가 포함될 수 있다. 원본 토큰과 학생 정보를 SQL 문자열에 넣지 않는다. Cloudflare 문서상 바인딩된 SQL 매개변수는 D1 Queries 지표에 수집되지 않지만, SQL 문자열은 수집된다. 지표의 보존기간과 제공자 내부 보존 범위는 추가 확인한다. [D1 지표 안내](https://developers.cloudflare.com/d1/observability/metrics-analytics/)
- Cron 트리거의 다음 실행 시각은 표시되고, D1 Queries 지표에서 만료 조회 SQL이 최근 24시간에 21회 실행된 것으로 보인다. 다만 최근 일주일의 Cron events 목록은 비어 있다(2026-11-14 확인). 2026-11-14 가상 만료 PNG 1개로 다음 정각 예약 실행 후 D1 행 1→0건과 R2 객체 삭제를 확인했다. 기존 세 가상 링크도 정상이다. Cron events 화면이 비어 있었던 이유는 별도 조사 대상으로 남긴다.
- 실제 자료의 비공개 원격 등록·수신자 대조·원본 삭제 예정일 기록 절차를 마련하고, 위 확인 결과를 기록한다. 확인 전에는 실제 자료를 Cloudflare에 올리지 않는다.

## 백업에 관한 제공자 동작

별도 파일 백업을 만들지 않더라도 Cloudflare D1의 Time Travel 복구 이력은 기본으로 활성화되어 있으며 Workers Free에서 최대 7일 전으로 복원할 수 있다. D1에는 안내장 파일 자체나 원본 링크 토큰을 저장하지 않고, 객체 키·형식·만료 시각과 토큰 해시를 저장한다. R2 파일은 앱의 30일 정리 대상이며, 제공자 내부 보존·로그의 상세 범위는 실제 자료를 올리기 전에 확인한다. [Cloudflare D1 Time Travel 안내](https://developers.cloudflare.com/d1/reference/time-travel/)

보유기간이 지나거나 처리 목적이 끝나 불필요해진 개인정보의 파기, 안전조치, 처리 목적과 보유기간을 포함한 처리방침을 운영 단계에서 검토한다. 참고: [개인정보 보호법 제21조](https://law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029334977), [제29조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900079357), [제30조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1006185717).

다운로드 받은 사본은 받는 사람의 기기에 남는다. 링크 폐기나 서버 원본 파기는 이미 내려받은 사본을 회수하지 못한다.

링크 재발급은 관리 복사본의 만료일을 연장하지 않는다. 로컬 서버가 중단되었을 때는 다음 시작 시 만료 파일을 정리한다. Cloudflare 데모는 만료 즉시 열람을 차단하고 매시 예약 작업으로 R2 복사본과 D1 기록을 정리한다. 2026-11-14 가상 만료 자료 1건으로 예약 작업의 D1 기록과 R2 복사본 삭제를 확인했다.
