# 설계 결정

## 2026-11-14 · Cloudflare 모바일 열람 화면

- 링크와 R2 객체를 확인한 후에만 모바일 화면 HTML을 제공한다. 화면의 이미지·PDF 요청과 다운로드도 동일한 링크 검증을 통과한다.
- 기존 가상 이미지 화면과 PDF.js 뷰어를 정적 파일로 빌드하고, 유효한 링크의 화면에서만 토큰별 파일 경로를 주입한다. 정적 빌드에는 실제 안내장을 넣지 않는다.
- 실제 Cloudflare 바인딩과 휴대폰 브라우저 동작은 배포 후 확인한다.

## 2026-11-14 · 비공개 R2 파일 제공 경로

- Worker는 먼저 D1에서 링크의 활성·만료 상태를 확인한 다음 R2 객체를 읽는다. 요청 URL에 R2 객체 키를 넣지 않는다.
- 파일 열람과 다운로드만 구현한다. 등록·삭제·목록·관리 API는 만들지 않는다.
- 화면과 Cloudflare 배포는 후속 변경으로 진행하며, 실제 학생 자료는 사용하지 않는다.

## 2026-11-13 · Cloudflare 링크 저장소 준비

- Vercel에는 가상 긴 이미지 정적 데모만 유지하고, 온라인 링크·PDF 검증은 별도 Cloudflare Worker에서 진행한다.
- D1에는 안내장 파일 자체나 원본 링크 토큰을 넣지 않는다. 안내장 메타데이터와 SHA-256 토큰 해시, 만료·폐기 상태만 둔다.
- 비공개 R2 파일 제공과 만료 복사본 삭제는 별도 PR로 구현한다. 이 단계의 코드는 아직 배포되지 않았다.
- [구현 범위와 다음 단계](cloudflare-link-store.md)를 따른다.

## 2026-11-13 · 첫 샘플 뷰어

- 실제 자료 없이 긴 SVG 이미지로 모바일 읽기 동작을 먼저 검증한다.
- 현재 샘플만 공개한다. 이 단계의 URL은 학생별 접근 링크가 아니다.
- Node.js 내장 기능만 사용해 로컬 실행과 빌드의 진입 장벽을 낮춘다.
- 실제 안내장을 추가하기 전에 서버 전용 저장소, 무작위 링크, 폐기·재발급, 로그 최소화를 구현한다. `dist/`에는 실제 자료를 넣지 않는다.
- 하네스는 `AGENTS.md`, 이 결정 기록, `npm run check`, GitHub Actions, PR 양식으로 시작한다. 실패 사례가 나오면 해당 규칙 또는 검증을 보강한다.

## 2026-11-13 · 샘플별 접근 링크

- 서버가 32바이트 난수로 링크 토큰을 만들고 원본 대신 SHA-256 해시를 `private/links.json`에 보관한다. 파일은 Git에서 제외한다.
- 공개 데모와 링크 전용 샘플을 분리한다. 링크 이미지 두 개는 공개 정적 빌드에 넣지 않고 서버의 허용 목록으로만 읽는다.
- 발급·폐기는 서버 로컬 CLI에서만 수행한다. 공개 관리 API나 인증 시스템은 만들지 않는다. 같은 샘플을 재발급하면 기존 링크는 무효화한다.
- 링크 응답은 캐시를 막고 리퍼러와 검색 색인 노출을 줄인다. 서버는 요청 URL과 토큰을 기록하지 않는다.
- 이 단계는 로컬 샘플 검증이다. 실제 자료를 운영하기 전에 영속 저장소, 백업·폐기 정책, 배포 환경의 접근·로그 설정을 검토한다.

## 2026-11-13 · PDF 웹 읽기

- 샘플 PDF는 코드에서 생성하고 토큰이 유효할 때만 서버가 제공한다. PDF 원본 파일은 공개 정적 빌드와 Git에 넣지 않는다.
- 같은 서버의 PDF.js와 worker가 각 페이지를 캔버스에 그려 별도 앱 없이 스크롤로 읽게 한다. 외부 CDN을 요청하지 않아 링크 토큰이 제3자에게 전달되지 않는다.
- 렌더링 해상도는 기기 픽셀 비율 2배로 제한한다. 현재 샘플은 2페이지이며 긴 실제 PDF의 메모리·성능은 별도로 검증한다.

## 2026-11-13 · 로컬 PNG 검증

- 사용자가 제공한 `uploads/testImage2.png`를 `local-image` 링크로만 읽는다. 원본은 Git과 공개 정적 빌드에 포함하지 않는다.
- 로컬 파일용 페이지에는 샘플 자료라는 문구를 표시하지 않는다. 공개 데모의 샘플 문구는 그대로 둔다.
- 서버는 기본적으로 루프백 주소에만 연결한다. 실제 자료의 휴대폰 접속과 배포는 접근·보관 정책을 정한 뒤 검증한다.

## 2026-11-13 · 실제 안내장 자료 범위

- 실제 안내장에는 학생 이름과 학년뿐 아니라 점수와 교사 의견도 담는다.
- 링크 유효기간, 원본·백업 보유기간, 외부 배포 환경은 [데이터 운영 결정](data-policy.md)에서 확정한다. 그전에는 실제 자료를 로컬에서만 검증한다.

## 2026-11-13 · 링크 만료와 다운로드

- 현재 링크만 가진 사람이 열람하며 회원 기능은 나중에 추가한다. 링크는 발급 후 30일에 자동 만료한다. 만료 시각이 없는 기존 링크는 다시 발급한다.
- 유효한 링크에서 이미지와 PDF를 원본 형식으로 다운로드할 수 있다. 파일 이름은 학생 정보가 없는 일반 이름을 사용한다.
- 운영 원본의 보관기간은 30일로 정했다. 자동 파기의 기산점과 사용자 PC의 `uploads/` 원본을 다룰 범위는 별도로 확정한다.

## 2026-11-13 · 앱 관리 복사본 30일 보관

- PNG·JPG·PDF 파일을 `uploads/`에서 등록할 때 앱 전용 `private/managed/`로 복사한다. 복사본과 등록 기록은 Git과 공개 빌드에 넣지 않는다.
- 등록일부터 30일이 지나면 링크와 파일 열람을 막고, 서버 시작 시와 실행 중 1분마다 관리 복사본을 삭제한다. 서버가 꺼져 있었다면 다음 시작에 삭제한다.
- 재발급한 링크의 만료 시각도 복사본의 만료 시각을 넘지 않는다. `uploads/` 원본은 사용자가 직접 관리하며 자동 삭제하지 않는다.
